# Crawler's Companion for iOS — design

The whole companion as a native app: floors, who and what, every entry's story, the books' own
awards, search and the achievement generator, working with no network and sealed at the chapter
the reader has named. It ships with a copy of the content and replaces it when the site
publishes a newer one.

## What was asked for, and what was assumed

Asked for: a native iOS app; the whole companion, offline; able to pull new content from the web
companion; for the owner's own devices; with the books' awards, the achievement generator and an
iPad layout in the first version.

Assumed: the gate stays the product, so the app is at least as strict as the site; content is
authored in this repo and never edited in the app; the timeline (`/when`), accounts, position sync
and widgets are out.

## Where it lives

- A sibling repo, `~/Sites/dcc-companion-ios`, the arrangement the KOReader plugin already has.
  One source of truth for content, and it is here.
- SwiftUI, iPhone and iPad, iOS 26.0 minimum, Swift 6 language mode, strict concurrency complete,
  warnings as errors — Arandor Compendium's settings. Bundle id `innovativStudio.CrawlersCompanion`,
  display name *Crawler's Companion*.
- The Xcode project is generated by XcodeGen from a committed `project.yml`; the generated
  `.xcodeproj` is committed too so the repo opens without a tool. `project.yml` is the source.

## The export, and the feed (this repo)

`npm run export:app -- --out <dir>` (`scripts/export-app.mjs`, `scripts/lib/app-export.mjs`) reads
the committed snapshot and writes three files. It runs under `--experimental-strip-types` so it
imports the real `src/lib` modules — `progress.ts`, `spoiler.ts`, `aliases.ts`, `quickfind.ts`,
`awards.ts` — rather than a copy.

### `content.json` (schema 1)

Every gate comparison is an integer `key` (the snapshot's `sortKey`, or `parseAt` of a tag where
the snapshot has none). No reveal-tag string survives, and a test fails on one.

```
{ schema: 1, source,
  books:     [{ id, title, blurb, chapters, accent, ink }],
  floors:    [{ id, name, book, bookSpan, accent, ink,
                nameKey,                // the name alone (nameAt, or arrival when absent)
                key,                    // arrival: premise and previously
                premise, previously,
                parts: [{ key, span, title, text }] }],
  entities:  [{ id, kind, name, role, voice, sort, key,
                aka: [{ name, key }],
                taglines: [{ key, text }],
                descriptions: [{ key, stamp, text }] }],
  beats:     [{ id, entity, key, book, chapter, floor, use, headline, text, voice, draft }],
  relations: [{ from, to, kind, note, key }],
  awards:    [{ id, name, key, at, floor, forWhat, box, tier, text, reward,
                recipients, everyone, source, draft }] }
```

- Beats are sorted by `key` and numbered from 1 in that order, so **the reached beats are always a
  prefix**, and a beat's `id` is stable within a content version (which is all a search hit needs).
- A beat's `kind` is not exported. `use: true` is the one bit a view needs (the usage log of an
  item or mechanic); *fate* never leaves this repo.
- `book` and `chapter` on a beat are its own, for the stamp. `key` is what gates it.
- `span` on a recap part and `stamp` on a description are pre-rendered (`Book 3 · Ch 8–13`,
  `Book 4 · Ch 15`). The page's `span()` moves to `src/lib/stamps.ts` so the front page and the
  export share one implementation.
- An award carries `key` (when it may be shown) and `at` (when it happened, as an integer); `tier`
  comes from `tierOf`, so the box ladder is not re-derived in Swift.
- `voiceNote`, `confidence` beyond a `draft` flag, and anything else the app does not render are
  left out.

### `manifest.json`

`{ schema, version, generatedAt, bytes, counts }`. `version` is the SHA-256 of `content.json`'s
bytes. The snapshot is committed and the export is deterministic, so the version changes only when
content does. `generatedAt` is when the export ran (on the server: when the process built it).

### `gate-fixtures.json`

The proof that the Swift gate is the site's gate. For eleven positions — none, `1:1`, `1:22`,
book 1 finished, `2:3`, `3:19`, `5:40`, `5:75` (a last chapter, which is `:end`), `6:32`, `8:end`,
and everything shown — it records what **the site's own code** reveals: the frontier, the met
entity ids, the aliases seen, the tagline index in force per entity, the description index, the
count of reached beats, shown/sealed/next for a few named entries, relation counts, per floor
whether the name and the floor are open and how many parts, the reached award ids with the sealed
count and next key, and the Progress counts. It also records `quickFind`'s answers for a handful of
queries at several positions, so search ranking is pinned to the site's too.

### Served by the site

`/app/manifest.json` and `/app/content.json` are endpoints that run the same export function over
the bundled snapshot, once per process. Both send `x-robots-tag: noindex`, an `etag` of the
version and `cache-control: public, max-age=300`. Nothing links to them.

This is not a new exposure. *Show everything* already hands the same content to anyone as HTML;
the gate protects a reader from spoilers and was never access control.

`scripts/test-export-app.mjs` joins `npm run test:gate`; `npm run smoke` gains both routes.

## Updates on the device

- The bundle carries `content.json` and `manifest.json`, so first launch needs no network.
- A downloaded copy lives in Application Support. At launch the app uses it when it exists, its
  hash verifies and its schema is the one this build reads; otherwise the bundle. If the bundle's
  `generatedAt` is later than the download's (the app was updated), the bundle wins.
- **The check**: at launch, and on returning to the foreground when the last check is more than an
  hour old, fetch the manifest. If its `version` differs from the active one, its `schema` is
  supported and its `generatedAt` is later, download `content.json`, verify the hash against the
  manifest, decode all of it, then write it atomically and swap the in-memory library.
- **A failure changes nothing.** No network, a bad hash, an undecodable file, a newer schema, or a
  server whose content is older than the app's: the active copy stays, and Progress says which.
- Progress shows *Content from 4 Oct 2026* and a manual **Check for new content**, same rule.

## The gate in Swift

`Frontier.of(position, chapters:)` is `frontierOf`, exactly: book 0 is `FRONTIER_NONE`; chapter 0,
or a chapter at or past the book's last, is `999`; everything shown is `9000`.

**Views never receive raw content.** `Library` holds the decoded export, and its stored content is
internal to the package. The only public way in is `library.reader(state)`, which returns a
`Reader` — a value built for one position that hands out only what has been reached:

| asked | answered |
|---|---|
| `entries` | met entries only, in the site's order (kind, sort, name), each with its tagline in force, reached aliases and `shown/total` coverage |
| `page(for:)` | `nil` for an unmet id; otherwise the description in force, usage log and story split into shown beats, a sealed count and the next key, reached relations and a sealed count |
| `floors` | per floor: the name if open (else none), the premise and reached parts if arrived, sealed part count and next key |
| `opening` | *welcome* with no position, else the *previously* text of the floor stood on and the status line's facts |
| `awards` | reached awards, the sealed count, the next key; never a sealed award's name |
| `find(_:)` | hits among reached names, reached aliases, the tagline in force and reached beats |
| `stats` | entries and timeline entries unsealed out of the total, as Progress shows on the site |

The compiler therefore stops a view from touching an ungated field — the app's version of *a
sealed row is not in the document*. An unmet entry is not listed at all, which is stricter than
`/who`'s redacted rows, and a beat's floor label names the floor only when that name is open.

The fixtures are the test: at every fixture position the Reader must reveal exactly what the site
does.

### Position

`ReadingState { book, chapter, showEverything }` in `UserDefaults`, with the cookie's meaning:
book 0 is *nothing told*, chapter 0 is *finished* and only ever comes from the button that says
so. No account, no sync with the site.

## Screens

One `TabView` with the sidebar-adaptable style, so it is a tab bar on iPhone and a sidebar on iPad.

| tab | contents |
|---|---|
| **Floors** | The System's opening block — *Welcome, viewer* and the back cover, or *Previously, on Dungeon Crawler World* and where the reader stands. Then the floors as disclosure sections, the current one open: number on its book's colour, the name (or a redaction), `Read · 4 parts` / `Sealed`; inside, `*** Now entering ***` and the premise, the reached parts with their span stamps, one sealed line. |
| **Who & What** | Met entries grouped by kind; a name filter; kind chips with counts of met entries. No position: the System's *No position set* block and a disabled filter. On iPad a list-and-detail split. |
| **Awards** | *From the books*: reached awards banded by floor (`In order`), or flat by `Latest` / `Name` / `Box`; tier chips counted over reached awards; word-start search; a sealed tail computed from `key` whatever the sort. A row opens the System's text in full, the earners (linked), the reward and the source link. *File a report*: the generator. On iPad a split. |
| **Progress** | Position, what it unseals, *Show everything*, the content date and **Check for new content**, about. |
| **Search** | Quick-find: *Names* and *In the story*, typed words lit in gold, `*** No record ***` in blood. A story hit opens the entry scrolled to that line and marks it; a book filter hiding it is cleared. A floor hit opens Floors at that floor. |

**Entry page**, pushed from anywhere: kind and role, name, the tagline in force (with the quote
mark when the character speaks), *Also known as* with reached aliases, the System's description
with its stamp, book chips once there are more than twelve reached entries across more than one
book (counts of reached entries), *Where it's used* for items and mechanics, *Story so far* /
*History*, one sealed line per section, and connections that push the other entry with a
`*** N sealed ***` line. A beat renders the one way the site renders it: a System beat as a
`*** headline ***` block, a character's own line with the quote mark, `unverified` on a draft.
No `kind` label, ever.

**Position control**: a chip in every tab's toolbar — `Bk 3 · Ch 8`, `Bk 3 · finished`, *Set
position* in blood when unset, *Everything* when the gate is off — opening the picker as a sheet.
Eight book buttons in their own colours; choosing one shows its title, *Where are you in it?*, a
chapter slider starting at 1 (or the saved chapter for the saved book), and **Save · up to ch N**,
**I finished book N**, **Clear my progress**. Dismissing writes nothing.

## Look

The site's identity with native navigation. Ground `#131313` over `#0e0e0e`, gold `#ffc10a`,
blood `#e81514`, the greys and lines from `global.css`, the eight book colours with their inks
from the export. Dark only. Barlow Condensed for display, Inconsolata for anything the System
says, Open Sans for prose — bundled, all under the Open Font License — and sized through Dynamic
Type against the site's eight-step scale. Sealed content is the System's `*** Sealed ***` block,
never a blur.

Static copy typed into a view is ungated by construction, here as on the site. A test scans the
app's Swift sources for every entity, alias and floor name that is not safe at `1:1`, with
`check-pages.mjs`'s three rules (word boundaries; case-blind for a name of more than one word;
comments stripped) and its documented exemptions.

## The generator

- `POST /app/achievement.json` on the site, JSON in and out:
  `{ deed, surprise, book, chapter, spoilers }` → `{ grant: { title, citation, reward, tier, accent, ink, deed } }`
  or `{ problem: { head, body } }` (422 nothing filed, 429 throttled, 503 offline, 502 redacted).
- The page's request handling — the limiter, *Surprise me*, the lore drawn from what the reader has
  reached, the call, the in-character problems — moves to `src/lib/report.ts`, and the page and the
  endpoint both call it. One limiter, one prompt, one screen. The endpoint builds its gate from the
  posted position through the same clamps `readPrefs` uses.
- In the app: a field capped at 180 characters, **File report**, **Surprise me**, the grant card,
  and *Earned previously* — a local file capped at twelve, each row opening to the citation and
  reward. With no network the screen answers `*** Transmission interrupted ***` and everything else
  is unaffected. The heading carries the beta tag in blood.

## iPad

The tab bar becomes a sidebar. Who & What and Awards are `NavigationSplitView`s that collapse to a
stack on iPhone. Prose is capped at a reading width instead of stretching across the screen.

## Testing

1. **This repo**: `scripts/test-export-app.mjs` in `npm run test:gate` — no tag string anywhere,
   every key an integer, beats sorted and numbered, floors' keys, timed aliases, the manifest hash,
   fixtures present for every position. `npm run smoke` asserts the two feed routes.
2. **`CompanionCore`**, `swift test`: frontier arithmetic including *unspecified chapter means
   finished* and *book 0 reveals nothing*; the fixture comparison at every position; quick-find
   against the site's answers; the award filter and sorts; the content store's failure cases with a
   stub transport; the trophy cap; the static-copy scan.
3. **The app**: `xcodebuild` for an iPhone and an iPad simulator, and a UI test that launches with
   no position and finds no entry, then with `--position 1:22` and finds Carl but not a later name.
   Layout is checked by eye from simulator screenshots on both.

## Build order

1. Export, fixtures, feed routes and the generator endpoint in this repo.
2. `CompanionCore`, passing the fixtures.
3. Floors, Who & What, the entry page, Progress and the position picker.
4. Search.
5. Awards from the books.
6. The generator screen.
7. iPad layouts.

## Not in this version

The timeline, accounts or position sync, widgets, reading the position from an e-reader, push
notifications for new content, and App Store distribution — which would want the author's or the
publisher's blessing first.
